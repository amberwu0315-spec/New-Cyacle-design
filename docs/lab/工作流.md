# lab 工作流（同仓 L2）

> 定位：**决策沙盒**。产出是「证据 + 迁移清单」，不是可合并的产品代码。
> 边界：**只动前端呈现层**。不改 server、不改 domain 契约、不修 P0 安全项。
> 数据：**脱敏真数据**，同 server、同账号、同 `/api`。

---

## 0. 先纠正一个直觉：这个仓库很薄

`git ls-files` 只有 **356 个文件**：

| 内容 | 文件数 | 是否在 git |
|---|---|---|
| `domain/base/**` | 275 | ✅ 跟踪 |
| `app/**`（其中 `app/src/web` 50） | 60 | ✅ 跟踪 |
| `app.yaml` / `pnpm-workspace.yaml` / `plot.yaml` / `build.yaml` | 4 | ✅ 跟踪 |
| 其余 **37 个 domain** | — | ❌ 不跟踪（`.gitignore` 列出、`plot app apply` 本地 clone） |
| `app/src/server`、`.plot/**`、`**/generated/`、`dist/`、`go.work*`、`dev.yaml` | — | ❌ 忽略，全部生成 |

**推论一**：合并便宜，因为业务代码根本不在这个仓库里——冲突只可能落在 `app/src/web/**`、`domain/base/**`、`app.yaml`、`pnpm-workspace.yaml` 这四处。

**推论二**：别人的前端改动有两条通道，不能混为一谈：

| 通道 | 覆盖 | 同步手段 |
|---|---|---|
| A. 本仓库 | `app/src/web`、`domain/base` | `git merge origin/main` |
| B. 远程 domain 仓库 | 37 个 domain 的页面 | `plot app apply`（重新 clone/更新）后再生成本地依赖 |

只做 A 不做 B，会出现「类型对不上、页面 404」的假故障；只做 B 不做 A，lab 的壳还是旧的。

## 1. 分支与所有权

```
main                 ← 正式主干，永远不含 web.lab
└─ lab               ← 实验主干，长期存在
   └─ exp/<name>     ← 仅在「两个实验要同时改壳层」时开，合回 lab 后删除
```

目录所有权：

| 路径 | 归属 | 规则 |
|---|---|---|
| `app/src/web.lab/**` | lab | 随便改，没人会碰，冲突为零 |
| `app/src/web/**` | 共享（main） | **只读**。lab 需要改壳就复制进自己目录 |
| `domain/base/src/web/**` | 共享（main） | 只读；确实要改 = 升级为「回灌提案」，不在实验里做 |
| `app.yaml` / `pnpm-workspace.yaml` | 共享（plot 会重写） | 冲突高发区，见 §5 |
| `docs/lab/**` | lab | 实验记录、决策、证据索引 |

**核心不变量**：`app/src/web.lab/` 之外的改动越少，每周同步越便宜。一旦某次合并冲突超过 30 分钟，说明实验动到了不该动的层，应退回 lab 内包一层覆盖。

## 2. 起步（一次性，约 1 小时）

```bash
cd "/Users/wuyuhui/Desktop/💪New-Cyacle"
source .toolchain/env.sh          # 提供 plot / go / pnpm

git switch -c lab
plot art add-web web.lab          # 生成 app/src/web.lab/
plot app apply                    # 生成 modules.gen.ts / styles.gen.css / 虚拟包
plot art dev web.lab              # 起第二个 vite，走 /lab 前缀
```

验收标准（缺一条就先别开始实验）：

1. `http://127.0.0.1:7088/lab` 能用**真账号**登录并打开空壳；
2. `/api` 请求与主应用同源、同 cookie，不出现 401；
3. `plot app build web` 的产物里**没有** lab 代码。

> add-web 会在 server 侧增量补一个 Web 入口。这是可回退的改写，但要在第一次 apply 后确认 `git status` 里 `app.yaml` 的 diff 只有一行 artifact 声明。

## 3. 日常闭环

```bash
source .toolchain/env.sh
plot art dev web.lab        # 只跑 lab
plot app run                # 起整个应用；是否同时起两个 web 入口，第一次跑时确认
plot art dev web            # 需要干净基线做对照时，单独起主入口
```

写实验的顺序固定为：**先照抄 parity，再改造**。lab 的第一版就是 `app/src/web` 的复制（router + AppLayout + 生成物），跑到和新版逐像素一致，之后的差异才是实验变量。

对照要求：1280 / 1440 / 1920 三档，同 URL 参数、同账号、同数据。

## 4. 每周同步（建议周五，30 分钟预算）

```bash
cd "/Users/wuyuhui/Desktop/💪New-Cyacle"
source .toolchain/env.sh
git switch lab
git fetch origin
git merge origin/main          # 冲突只可能在 §0 说的四处
plot app apply                 # 必须在 merge 之后，且必须在仓库根执行
```

同步后必须过三关，任一失败当天不写新实验：

1. `plot app apply` 无报错，`git status` 干净（除 `docs/lab` 下的记录）；
2. `app/src/web` 和 `app/src/web.lab` 各自 `pnpm typecheck` 通过；
3. `/lab` 打开首页、项目列表、数据记录三页不白屏。

## 5. 合并检查清单

前四项会报错，会被发现；**后两项不会报错，只会悄悄错位**——这才是同步的真正成本。

- [ ] `app.yaml`：`web.lab` 的 artifact 声明还在，没被 main 的版本覆盖
- [ ] `pnpm-workspace.yaml`：`packages:` 里 plot 生成的 `./.plot/web/virtual/*` 列表与 `domain/*` 声明一致
- [ ] `app/src/web.lab/src/generated/**`：一律「取 theirs 再 apply」，不手改、不手工合并
- [ ] `domain/base` 新增/删除的导出：lab 里 import 的符号是否还存在
- [ ] **`domain/base` 组件签名变更**：lab 手抄的那份 shell 不会自动跟着变，需要逐条对照 `BaseAppLayout` / `DataView` 的 props
- [ ] **`app/src/web` 的导航配置变更**：lab 的 nav 是从旧版抄来的，main 新增的场景/权限分类不会自动出现

第 5、6 项的做法：`git diff origin/main@{1}..origin/main -- app/src/web domain/base` 把改动过一遍，只挑影响 props / nav 配置 / 路由注册的部分，人工核对 5 分钟。

## 6. 冲突裁决三条规则

1. **共享文件冲突，一律取 main**，然后回到 lab 里包一层覆盖。理由：lab 是沙盒，没有「我的版本更对」这种说法。
2. **`app/src/web.lab/**` 永不接受别人版本**。这个目录只有你写。
3. **拿不准是否属于「呈现层」的改动，按不属于处理**：停下来，转成 `docs/lab/提案/<编号>.md`，回主仓走正式排期。

## 7. 实验包模板（每个实验必须交齐）

1. 假设 + ≥2 个候选方案（只有一个方案的实验不要开）
2. 3 个真数据场景，至少含 1 个长名称 / 异常状态 / 非企业组织
3. 证据：三档对照截图 + 关键交互录屏
4. **反事实证明**：旧版在哪个场景下更好（缺这条，结论默认不采信）
5. 迁移清单：要动 `base` 哪几个文件、`domain` 哪几个页面、波及 79 个 `DataView` 文件中的哪些
6. 决策记录：结论 + 不采纳方案的理由 + 预估工时

存放：`docs/lab/<编号>-<主题>/`，`README.md` 是决策记录，截图放 `evidence/`。

## 9. 不做什么

- **不在 lab 里修 P0 安全与数据正确性**（多租户、假 total、批量部分写入）——这些唯一解，回主仓修 + 补测试。
- **不承接客户交付分支**——按合同验收的形态大改单独走交付线。
- **不追求 lab 代码可合并**。丢弃是默认结局；能被搬走的只有少量设计 token 和纯展示组件。
- **不把 lab 当演示环境**。要对外演示，再评估独立仓库/独立部署，那是另一个决策。
- 涉及双 agent（实现/测试分离）时，按 `AGENTS.md` 要求用 `multi-agents-dev-mode`，不要用本文的 worktree 方式替代。

## 10. 关于 worktree

只有在「同一时刻需要两个独立 checkout」时才用（两人并行、或要保住一个干净基线做对照）。代价要先知道：

- 新 worktree 只有 356 个跟踪文件，**没有** `.toolchain/`、`.plot/`、`app/src/server`、37 个远程 domain；
- 首次要复制/改写 `.toolchain/clone-domains.sh`（其中路径写死在主目录）重新 clone 全部远程 domain，再 `plot app apply`，一次 10~30 分钟且依赖内网；
- `git worktree add` 的路径一律用绝对路径。

```bash
git worktree add "/Users/wuyuhui/Desktop/cyacle-lab" lab
git worktree list
git worktree remove "/Users/wuyuhui/Desktop/cyacle-lab"
```

否则默认就用单工作目录切分支——同步免费、磁盘零浪费，代价只是不能同时开新旧两个 dev server（先确认 `plot app run` 会不会同时起两个 web 入口；不会就分别 `plot art dev web` 和 `plot art dev web.lab`，让两边都挂到 7088 下对照）。
