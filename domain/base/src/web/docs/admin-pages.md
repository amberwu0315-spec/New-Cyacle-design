# Admin 页面展示规范

[← 返回 Web 文档入口](../web.md)

> 职责：约束 `/admin/**` 页面中的详情信息、内容分区、业务跳转和结构化数据展示。后台改动仍需遵守 [Admin 改动隔离](routing-and-layout.md#admin-改动隔离)，不能影响前台路由和前台样式。

## 详情信息与技术标识

- 面向业务用户的详情页不展示数据库主键、UUID、`orgId`、`userId`、文件 ID 或其他 `xxId` 技术标识。
- 不使用 ID 兜底业务名称、简称、组织名称、操作人、联系方式或下拉选项说明；业务名称为空时使用项目统一空值文案。
- 排障、审计和接口联调页面只有在技术标识本身属于明确产品需求时才能展示，并应使用完整字段名说明含义。
- 页面标题展示业务名称；标题下不重复展示实体 ID。创建人、更新人等审计信息优先展示可识别的用户名和时间。

## 业务对象跳转

- 详情页出现用户、组织、角色、方案等业务对象，且 Admin 已存在对应详情路由、当前用户也有访问权限时，名称应作为链接或链接样式按钮跳转到该后台详情页；无权限时回退为普通文本。
- 跳转入口使用业务名称、用户名等可识别文本，不显示或要求用户点击裸 ID。
- 不为了“可跳转”拼接不存在的路由，也不从 Admin 详情页跳到视觉和权限边界不同的前台详情页；没有后台详情路由时保持普通文本。
- 表格的主业务名称列承担详情跳转；行尾操作区只放编辑、移除等动作，不重复添加“查看详情”。

## 分区与边界

- 详情页面使用“页面标题 → section 标题 → 内容”的稳定层级。section 之间通过间距、浅背景色和内容密度区分。
- 避免“页面边框 → section 边框 → 卡片边框 → 表格边框”的多层描边。推荐 section 使用无边框浅色背景，内部只有表格、输入控件等确实需要边界的组件保留自身边界。
- 普通键值信息可以使用同色系背景块分组，不为每个字段增加下划线、分割线或独立描边。
- 状态、类别等真实业务语义可以使用 Badge；空值直接显示 `-` 或领域约定的空值文案，不把空值包进 Badge。

## 关联数据与表格

- 账号、订阅方案、服务企业、关联角色、操作日志等结构化集合优先使用通用 `DataView` / `DataGrid`、`useDataModel` 和 `createDataColumnBuilder`。
- 数据表必须有可见表头，列名应能独立说明含义；不要用 CSS Grid 或固定宽度 `div` 模拟无表头表格。
- 表格加载使用通用 skeleton，无数据使用明确空状态；表格自己的滚动区域不能带动页面标题和 section 标题滚动。
- 表格所在 section 使用浅背景承载时，不再为 section 增加外框，由通用表格保留唯一的数据区域边界。
- 树、时间线、键值描述和单对象摘要不强制表格化，但必须保留清晰的层级或字段语义。

## 修改检查

- [ ] 页面标题、主体信息和树节点没有展示技术 ID，也没有用 ID 兜底名称。
- [ ] 已有后台详情路由的业务名称可以跳转，且目标仍位于 `/admin/**`。
- [ ] section 没有边框套边框，背景色、留白和标题层级足以区分内容。
- [ ] 结构化集合使用通用表格并有表头；加载、空数据和滚动状态完整。
- [ ] 只影响 Admin 页面，前台路由、组件外壳和全局样式没有被带动修改。
